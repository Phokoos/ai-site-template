# 4. Plan

## Purpose

Produce the **Plan** artifact for one feature using the repository's own language, framework, commands, and conventions.

## Before starting

Read the previous stage artifact. If it is missing or insufficient, stop with `BLOCKED` rather than guessing.

## Procedure

1. Read relevant repository files and prior artifacts.
2. Apply the questions below.
3. Record decisions and evidence in the stage artifact.
4. Check the gate before handing off.

## Questions and checks

- Which files and components will change?
- What is the smallest safe implementation sequence?
- What checks map to each acceptance criterion?
- What risks, dependencies, rollback, or migration concerns exist?

## Gate

The artifact is ready only when it is complete, evidence is honest, and no blocking question remains. For Review, the status must be `PASS`; otherwise use `READY` or `BLOCKED`.

## Handoff

Use the standard handoff format from `AGENTS.md`, including the exact artifact path and next stage.
