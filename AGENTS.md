## Перед будь-якою задачею

1. Прочитай `context/README.md` і файли, на які він веде (ТЗ, поточний стан, нотатки).
2. Фічі, сторінки, секції і нетривіальні фікси робимо за процесом **Simple SDD** — скіл `/sdd <feature>` (`.agents/skills/sdd/`), артефакти в `docs/features/<feature>/`. Зупиняйся на кожному гейті й чекай підтвердження.
3. Під час написання коду дотримуйся `andrej-karpathy-skills:karpathy-guidelines`: мінімальні, хірургічні зміни.

Зміни UI додатково перевіряємо в браузері (`claude-in-chrome`): усі мови сайту на ширинах 1440, 834 і 390 px.

## Правила

- Працюємо **строго за ТЗ** (`context/`). Поведінку продукту (тексти, візуал, обсяг) не вигадуємо — питаємо.
- Ключі й секрети — лише в `.env`, ніколи в git, логах чи браузері; значення вписує власник.

## Скіли

Проєктні скіли лежать у `.agents/skills/`, а `.claude/skills` — це симлінк на цю папку. Нові скіли встановлюй через `npx skills add …`, щоб вони оновлювали `skills-lock.json`. Скіл `sdd` вендорений (Phokoos/simple-sdd, коміт `d045c48`) і в `skills-lock.json` не значиться.

| Скіл | Для чого |
|---|---|
| `sdd` | процес фічі від контексту до релізу |
| `frontend-design` | візуальний напрям, типографіка, нешаблонний дизайн |
| `emil-design-eng` | полірування UI, деталі компонентів |
| `improve-animations` | аудит і план покращення анімацій |
| `bento` | модульні сітки з карток |
| `web-design-guidelines` | ревʼю UI на доступність і best practices |
| `andrej-karpathy-skills:karpathy-guidelines` (плагін) | дисципліна змін у коді |
